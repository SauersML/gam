WORK ITEM: p-values: permanent calibration benchmark (size/power grid vs pyGAM) and docs page
Build the permanent, reproducible p-value calibration harness that the pv-* lanes' fixes are measured by, and that shows users gamfit's p-values are valid where pyGAM's are not.
- bench/pvalue_calibration/: a seeded grid over family (gaussian, binomial, poisson, gamma, negbin at least) x n (60, 200, 1000, 5000) x null structure (null smooth beside real smooth, null linear coefficient, null factor, null ti interaction, null random effect, concurvity 0.9) x surface (summary Wald p, smooth_significance p, coefficient p). Outputs: size at 0.10/0.05/0.01 with MCSE, KS statistic, power on a matched alternative, and pyGAM's size/power on the same data where pyGAM has a counterpart. Resumable, parallel (process pool), memory-bounded; follows the design of bench/pygam_compare (reuse its worker infrastructure rather than duplicating it).
- A fast CI-sized subset (a few cells, ~200 reps, fixed seeds) as a regression test with tolerances derived from MCSE (not hand-picked), and a nightly-sized plan.
- docs: a page (docs/) explaining which p-values gamfit reports, what each tests, the reference distributions, and the calibration table (regenerate from the harness). Coordinate with claude/pygam-docs.
- Do not fix p-value bugs yourself — file what you find in your PR description with the exact failing cells so the owning pv-* lane (listed above) can fix it; if a failing cell has no owner, fix it only if small.
- Acceptance: harness runs end to end on the quick plan; smoke test passes; docs page renders.

P-VALUE PROGRAM CONTEXT (applies to every pv-* lane): the user considers ANY wrong p-value unacceptable. A p-value is correct only when, under its null, P(p <= a) <= a for every a (valid), ideally ~= a (sharp), across n, family, term type, and nuisance structure. Every lane must:
- Measure first. Build a seeded Monte Carlo calibration study (as a Rust or Python test in tests/ or crates/*/tests, or a bench script under bench/pvalue_calibration/<lane>/ plus a smaller seeded regression test), with enough reps that the Monte Carlo SE at alpha=0.05 is <= 0.01 (>= 500 reps where feasible; fewer only for expensive cells, stating the MCSE). Report size at 0.10/0.05/0.01, a uniformity check (KS against U(0,1) on the null p-values), and power on a non-null alternative.
- Fix the construction on principle (correct reference distribution, correct df, correct covariance, correct treatment of boundary nulls, of smoothing-parameter selection and of estimated scale). No fudge factors, no empirical "calibration multipliers", no magic constants, no alternative p-value variants left for the user to pick between (SPEC: unnecessary options are deleted). If a p-value cannot be computed validly for some model class, return a typed "unavailable, with reason" rather than a number.
- Put the logic in Rust (Python and CLI only read fields), and keep CLI/Python/Rust parity.
- Read bench/pygam_audit/inference.md on the audit branch (also slop.md G4 and G6) before starting. inference.md sections 3.2 and 4 hold the current calibration evidence.
