WORK ITEM: convergence + accuracy on real datasets (pyGAM datasets, mgcv classics, UCI) vs pyGAM
Real data breaks solvers in ways simulations do not. Fit gamfit and pyGAM (pygam and pygam_gs) on: all pyGAM datasets (fetched via the bench fetcher, never vendored; see bench/pygam_audit/accuracy/bench_accuracy.py on the audit branch), classic GAM datasets available from public URLs (e.g. mgcv-style examples re-created from R dataset CSVs on the web: mcycle, airquality, CO2, gamSim-like data; UCI: bike sharing, California housing, abalone, concrete, wine quality, adult income for binomial), each with a sensible default formula (and gamfit's auto formula if main has it).
- Metrics: certification, wall time, peak RSS, held-out deviance (5-fold CV with fixed seeds), interval coverage on held-out data where applicable.
- Fix unowned failures at the root; list owned ones for owners.
- Output: a real-data leaderboard under bench/real_data/ (script + results + README), data fetched at run time with checksums, never committed.
- Acceptance: leaderboard committed (results JSON + markdown); every dataset certifies; before/after for each fix.

SWEEP PROGRAM CONTEXT (applies to every sweep-* and conv-* lane): the user wants gamfit to beat pyGAM on speed and convergence everywhere, with no exceptions, by fixing root causes — never by caps, budgets, fallbacks, looser tolerances, jitter or skipping work that correctness needs (SPEC). gamfit does strictly more work than pyGAM's default (REML selection of one lambda per penalty, smoothing-corrected covariance); the fair speed comparator is pyGAM gridsearch (`pygam_gs` in the harness), but the goal is to beat pyGAM's plain default fit too wherever that is achievable without giving up correctness.
- Tooling: bench/pygam_compare on main (read its README; plans in plans.py). Extend plans.py with the cells your lane needs rather than writing a new harness. speed.md, robustness.md and accuracy.md on the audit branch hold earlier measurements.
- Method: (1) run your sweep and produce a table of every cell where gamfit is slower than pyGAM, fails to certify, raises, hangs (use the harness's per-rep subprocess isolation to detect hangs — a hang is a bug, never "add a timeout"), or uses more memory; (2) profile the worst cells (perf / cargo flamegraph / RUST_LOG timing) and find the root cause; (3) fix it in the engine; (4) add a regression test (a fixed-seed fixture that must certify, or a bench-plan cell with a documented baseline); (5) re-run the sweep and put before/after tables in the PR.
- Many sessions already own specific slow/non-converging paths.
