WORK ITEM: p-values: random effects and fully-penalized terms (boundary null, chi-bar-square), calibrated
Surface: tests for group()/re() random-effect terms (variance component = 0 is on the boundary of the parameter space) and for smooths whose null space is fully penalized by the double penalty (null = zero function, also a boundary).
- A naive Wald/LR with a chi2 reference is wrong on the boundary: the correct asymptotic null is a chi-bar-square mixture (e.g. 0.5 chi2_0 + 0.5 chi2_1 for one variance component; Self & Liang 1987, Stram & Lee 1994), or Wood's (2013) random-effect test (Biometrika 100:221-228) which uses an exact finite-sample spectral reference. Check what gamfit currently reports for re()/group() terms and for double-penalty smooths.
- Build null cells: y ~ s(x1) + group(g) with no group effect, g with 5, 20, 200 levels, balanced and unbalanced, Gaussian and binomial and Poisson; also the null double-penalty smooth.
- Fix on principle: exact or correctly-mixed reference; no halving heuristics without derivation. If gamfit does not yet report a random-effect test, add one (it is needed to beat pyGAM honestly), in Rust, surfaced in summary.
- Coordinate with claude/pygam-factor-contract (factor vs group semantics) and claude/pygam-group-scaling (group() with many levels).
- Acceptance: seeded calibration, size within 2 MCSE of nominal at 0.10/0.05/0.01 for each cell and KS against U(0,1) on the full range not rejected; the chi-bar-square atom at T=0 is handled by a seeded randomized p-value over the atom, so there is no point mass at p=1.

P-VALUE PROGRAM CONTEXT (applies to every pv-* lane): the user considers ANY wrong p-value unacceptable. A p-value is correct only when, under its null, it is U(0,1) over the whole range: P(p <= a) = a for every a, across n, family, term type, and nuisance structure. Conservative (P(p <= a) < a) is a bug exactly as much as anti-conservative. Every lane must:
- Measure first. Build a seeded Monte Carlo calibration study (as a Rust or Python test in tests/ or crates/*/tests, or a bench script under bench/pvalue_calibration/<lane>/ plus a smaller seeded regression test), with enough reps that the Monte Carlo SE at alpha=0.05 is <= 0.01 (>= 500 reps where feasible; fewer only for expensive cells, stating the MCSE). Report size at 0.10/0.05/0.01, a uniformity check (KS against U(0,1) on the full range of null p-values; the study fails on conservatism as well as anti-conservatism), and power on a non-null alternative.
- Fix the construction on principle (correct reference distribution, correct df, correct covariance, correct treatment of boundary nulls, of smoothing-parameter selection and of estimated scale). No fudge factors, no empirical "calibration multipliers", no magic constants, no alternative p-value variants left for the user to pick between (SPEC: unnecessary options are deleted). If a p-value cannot be computed validly for some model class, return a typed "unavailable, with reason" rather than a number.
- Put the logic in Rust (Python and CLI only read fields), and keep CLI/Python/Rust parity.
