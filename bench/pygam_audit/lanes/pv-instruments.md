P-VALUE PROGRAM CONTEXT (applies to every pv-* lane): the user considers ANY wrong p-value unacceptable. A p-value is correct only when, under its null, it is U(0,1) over the whole range: P(p <= a) = a for every a, across n, family, term type, and nuisance structure. Conservative (P(p <= a) < a) is a bug exactly as much as anti-conservative. Every lane must:
- Measure first. Build a seeded Monte Carlo calibration study (as a Rust or Python test in tests/ or crates/*/tests, or a bench script under bench/pvalue_calibration/<lane>/ plus a smaller seeded regression test), with enough reps that the Monte Carlo SE at alpha=0.05 is <= 0.01 (>= 500 reps where feasible; fewer only for expensive cells, stating the MCSE). Report size at 0.10/0.05/0.01, a uniformity check (KS against U(0,1) on the full range of null p-values; the study fails on conservatism as well as anti-conservatism), and power on a non-null alternative.
- Fix the construction on principle (correct reference distribution, correct df, correct covariance, correct treatment of boundary nulls, of smoothing-parameter selection and of estimated scale). No fudge factors, no empirical "calibration multipliers", no magic constants, no alternative p-value variants left for the user to pick between (SPEC: unnecessary options are deleted). If a p-value cannot be computed validly for some model class, return a typed "unavailable, with reason" rather than a number.
- Put the logic in Rust (Python and CLI only read fields), and keep CLI/Python/Rust parity.
